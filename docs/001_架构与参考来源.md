# 001 架构与参考来源

本次任务：参考两个公开项目，制作类似 UnrealBridge 的 Blender Bridge，包含 MCP 与 skills，作为后续塔与机甲重制工具。实现位于独立目录 `C:/dev/BlenderBridge`，未修改作为参考的 `C:/dev/UnrealBridge`。

## 来源与取舍

| [ahujasid/mcp-for-blender](https://github.com/ahujasid/mcp-for-blender) | `60d2a31b4632a7bc178f3dd636f7e68dfb5c8ae4`；`addon.py`、MCP server、README；MIT | Blender 插件与 Python MCP 分离、主线程执行、实际视图反馈 | 不接入其云端服务；任意 Python 默认关闭；使用有长度边界的 HTTP 请求和独立任务状态 |

上游仓库只保存在 `.tmp/references` 供审核，没有把其代码复制进发行插件。本实现为独立代码；许可证与来源已查阅。未启用上游第三方模型下载、付费生成或遥测配置。

## 组件

```text
Codex / 其他 MCP 客户端          命令行
          │ stdio                │
          └────── client.py ──────┘
                     │ loopback HTTP + token
              transport.py  (不访问 bpy)
                     │ submit / job / health / catalog
                 core.py 任务队列
                     │ Blender 主线程 timer（后台用同线程 pump）
              runtime.py → operations.py → bpy / BMesh
                     │
         .blend / PNG / FBX / audit JSONL
```

`catalog.py` 是公共操作契约与校验来源。MCP 不复制 Blender 实现，不缓存旧 scene handle，不自行重试写操作。主线程状态快照与任务状态可在渲染期间从网络线程读取，但快照不是渲染过程中持续更新的实时 bpy 查询。

## 操作上下文与错误语义

- 每次启动独立 session UUID；加载另一个 `.blend` 会更换 session，并使排队的旧会话操作失败。
- scene revision 在桥接写操作后增加，失败也增加以提示可能的部分修改；外部 depsgraph 更新也触发增加。对象采用场景中的精确名称定位，没有宣称跨文件持久对象 UUID。
- 每次操作用稳定 request ID 与参数摘要；重复相同请求返回同一任务，ID 与参数冲突拒绝。历史不自动驱逐，以免旧 ID 被执行两次。
- 任务状态 `queued/running/succeeded/failed/cancelled`。已接受命令断连后继续执行，可以查询；运行中的 bpy 操作无法安全终止。
- 没有原子事务与自动恢复。未知结果必须检查原 ID、产物和场景，不能以新 ID 重放。

## 文件与安全边界

监听只绑定 `127.0.0.1`，每会话随机令牌，拒绝带 Origin 的浏览器请求。发现文件位于用户目录；令牌不放进 MCP 响应、日志或仓库。它是同机自动化工具，不是多租户隔离系统，也不防御同用户程序。

内置写入限定输出根目录，读图片限定输出根或指定读目录；真实解析路径防止普通 `..`/链接逃逸。已存在文件默认拒绝覆盖，显式覆盖时先备份。MCP 图片读取校验登记的产物 ID、根路径、大小与 SHA-256。

`python.execute` 必须在运行时显式启用；它能执行任意本机 Python，完全不是沙箱，不能靠静态过滤声称安全。默认目录中不展示此能力。

## 当前未覆盖

不支持安全取消运行中的运算、原子回滚、跨会话任务继续执行、自动重拓扑/烘焙/雕刻、外部生成服务或 UE 导入。新能力应先增加 typed schema 与真实 Blender 验证，再进入技能。当前只实测 Windows Blender 5.2.2；插件声明最低 4.2 是加载边界，4.2/其他平台尚未验证。
