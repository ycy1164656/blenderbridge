# 导入模型的参考图精修

与 `$blender-bridge` 配合使用。默认流程是：制作概念图与独立正/侧/背参考图 → 用户用在线服务生成模型并提供或导入 → Blender 检查、调优和精修。仅有图片时完成图片交付就结束本阶段，等待真实模型；不直接用图片生成原生几何或基本体替代品。保持技能名兼容既有调用。

先读取项目规则、资产复用要求、当前批准概念图和现有模型的具体差异。工具改善迭代与证据，不保证模型自动达到参考图质量。

## 先建立可判断的目标

图片阶段：记录参考文件、尺寸/比例、正侧背与主要视角、材质语义、运动/部署结构和交付路径。概念图与三视图默认交付四张独立图片，不混为一张大图。参考只有一个视角时，把不可见结构的设计推断明确标出。不要把不同视角的生成图当作必然几何一致，不虚构工程尺寸。用户自行选择和使用在线生成服务；不要隐式上传图片或调用服务。

模型到位后：确认模型/贴图实际路径、来源哈希或已导入对象，保留原件与既有场景。检查单位、轴向、尺寸、可分离部件、融合/漂浮几何、拓扑、法线、UV、材质与骨架。记录本次可修改对象及固定 Before 视图，再列出有限的精修目标。仅修改格式转换或材质时，不扩大为整体重建。

通过 `reference.register/crop/mask/calibrate/validate/freeze` 保存原图、派生变换和冻结哈希，实际读取冻结图片后再制作计划。相同三分之四图不能改标签充当前、侧、背；未去背景、未知相机、姿势冲突和未见区域必须如实记录。

先精修一个代表性资产或局部结构，验证轮廓、表面层级、连接和镜头。将已导入模型与参考图的差异写成 `modeling.plan` 的局部修正步骤、固定镜头和保护部件。用 `modeling.submit` 渲染当前候选图，实际看图后登记 `review.record`，再用 `modeling.resume` 修正或推进技术检查。该闭环由 Codex 自主审阅和修形，不增加每轮用户确认；用户要求的审核点仍保留。

## 分阶段制作

1. **比例与轮廓**：以导入网格为起点，选择固定相机和正交前/侧/背视图，渲染灰模，与批准图比较大形、截面、负空间和外轮廓。锁定符合要求的区域，局部移动、重拓扑或修补错误结构；不从基本体重新生成整件资产，不用更多小零件掩盖大形差异。
2. **结构**：针对融合部件、破洞、缺失厚度、失真接缝/关节和承力件作局部修复。必要时在授权区域增补几何，用 inset/extrude/bevel、布尔/镜像/厚度等明确操作。表面要有可读平面和层级；机械连接不能浮空；塔的底座/旋转/升降/展开结构须能解释运动。每几次结构编辑检查网格、固定角度灰模和局部近景。
3. **材质与细节**：大形成立后才安排材质角色、UV、贴图与磨损。高对比材质不能弥补缺失体积，黑色缝线不能代替真实装甲厚度。避免大量均匀圆角造成玩具感。使用真实 seam/unwrap/pack/density 与重叠检查；数据纹理按 Non-Color、颜色纹理按 sRGB。投射必须声明相机并检查遮挡和未覆盖区域；high/low/cage 烘焙绑定冻结几何和 UV 哈希，实际查看贴图，不将常量图或空图默认判为高质量。
4. **运动与游戏资产**：视觉结构达到当前批准标准后再绑定骨骼、权重、动作、导出。检查零面积面、非预期开口/非流形边、法线、UV、权重归一、关节运动、回姿态、单位与轴向。开放壳体是否可接受取决于用途，不用单一“非流形=0”作通用艺术标准。
5. **交付与验收**：完成当前授权的精修后，以 `export.package` 保存可继续编辑的 `.blend`、纹理和精确对象的 FBX/GLB/OBJ，使用 `delivery.verify` 独立读回尺寸、轴、UV、骨架、deform 权重、动画范围和纹理。导出可能拆分顶点，不以顶点数完全一致作为错误条件。提交固定 Before/Final、多视图、局部图与真实差异说明。参考匹配、模型技术、桥接技术、UE 导入/运行、用户视觉接受分别报告。图片交付阶段不执行这些模型步骤。

## 质量门槛与迭代

- 默认候选 960×540，最终证据 1920×1080；项目另有约定则遵循。最多保留 2～3 个工作候选，历史证据和恢复备份不随便删除。
- 每次预览明确目标对象，检查画面有没有被默认 Cube、旧候选或道具遮挡。使用 `blender_view_image` 实际看图，不能只检查 PNG 存在。
- 先按清晰语义注册并锁定保留部件；局部修改使用显式范围、顶点选择或渲染相机反选。旧拓扑索引、旧相机、旧图片和旧 review 不能证明新候选。恢复检查点只追加新候选，保留旧现场；修正后沿固定镜头回看全局和局部。
- 闭环区别图片交付、Codex 实际判断、技术验证与用户接受。`fixture_protocol` 只测试协议；未关闭差异不得因恢复或换候选被静默丢弃。
- 自评未达到参考图时直接说明具体差距并继续修形；不把不合格候选交给用户替自己判断。没有新的实现路线时诚实说明能力限制。
- 用户要求中途审核时只在对应阶段等待，不反复索要已给授权。用户未要求每步审核时自主完成范围内迭代，但不能宣称用户接受。
- 当前 ShooterRoyal 塔/机甲重制：保留旧版本，使用新修订输出；先交付参考图并等待用户在线生成、提供或导入模型，再进行授权精修。此前 R2/R3 未通过视觉要求，不能因换用 Bridge 就称其合格。UE 写入走项目独立授权与精确保存规则。
