# 区域选区与拆件（0.3.0）

先查询当前会话的 `object.separate` schema。旧会话可能仍运行 0.2.0；安装升级不会热替换其模块，也不能把任务静默切到其他实例。

`selection.query` 的盒体、球体、高度、材质、顶点组和部件条件生成**顶点选区**；`selection.pick` 也可提供选区。传递完整的 `selection_id`，不要把最多 32 个 `sample_indices` 当成全量范围。evaluated 面索引不能当作 base 面索引。

区域拆分传入 `object`、`name`、`selection_id` 和显式 `face_policy`：

- `all_vertices`：一个面的全部顶点都属于选区才拆走；跨界面留在余件。
- `any_vertex`：一个面任一顶点属于选区就拆走，可能带走边界外邻接面。
- 两种规则都只选已有面，不沿包围盒边界切出新边，不自动判断“炮管/轮子”等语义部件。
- 材质条件先选顶点；共享顶点可能使邻接面的所有顶点也入选。要求精确按面材质划分时，检查 base 面并使用明确 `faces`。

已有精确面集合继续用 `faces=[...]`；不相连的部件用 `mode="loose"`。`faces` 与 `selection_id` 互斥；loose 模式不能混用选区或边界规则。选区过期、对象不匹配、空面选区、重复/越界索引和输出重名会拒绝执行。

需要保留原件时传 `keep_original=true`，在独立网格副本上拆分。返回 `original` 为保留原件，`source` 是 `<name>_remainder`，`created` 是 `<name>_001` 起的拆出对象。返回后先检查实际对象名，预览时仅选余件与拆件，避免原件重叠。默认 `false` 保持旧调用的原位拆分行为；原位拆分使原对象旧选区失效，部件区域映射需要重新指定。副本拆分保留原件的选区与部件保护。

操作检查 base 顶点位置、面绕序、完整几何覆盖、每面材质、全部 UV 层与逐角 UV、材质/贴图引用、顶点组权重、Armature 绑定和世界变换。拆分边界复制顶点是预期行为。Blender 原生 Separate 对新对象的材质槽绑定方式变化由封装保留回源设置。检查不等于重建或重新展开 UV。

Shape Keys 当前明确拒绝；共享网格先显式创建独立副本。修改器求值后的外形、平滑/自定义法线、其他自定义属性、美术效果不在 `preservation` 保证内，必须按任务另查，不能把它的 PASS 当成视觉接受。保留原件时若仍有 Subdivision/Bevel 等依赖邻接关系的修改器，拆分后的求值外形可能变化。

重要拓扑修改仍先做限定对象的 `checkpoint.create`。发生后置验证失败时可能已有部分结果：读原 job、检查对象和现场，不自动重试或回滚。临时索引属性会清理，部分对象获得独立 ID，原位拆分的旧选区会失效。不要为绕过这些错误改用任意 Python。
